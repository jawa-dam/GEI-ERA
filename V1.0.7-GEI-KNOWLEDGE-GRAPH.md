# V1.0.7 — GEI Unified Knowledge Graph & Relationship Layer

## Purpose

V1.0.7 adds a navigable relationship layer above the V1.0.6 Discovery index. It models how GEI systems and records connect without converting those relationships into claims of truth or authority.

## Implemented

- `/knowledge/` relationship surface
- Canonical node dataset in `knowledge/knowledge-data.js`
- Relationship engine in `knowledge/knowledge-engine.js`
- Responsive graph-style node/detail interface
- Category filters
- Node selection and neighbor inspection
- Recent-node memory using browser-local storage
- Direct links from graph nodes to their existing GEI systems
- Shared Platform Core, Session, Registry, and Unified Navigation integration
- SEO metadata and responsive accessibility structure

## Relationship model

Each edge contains:

- `from` — source node ID
- `to` — destination node ID
- `relation` — human-readable relationship type

Relationships include `connects`, `discovers`, `supports-provenance`, `feeds`, `related`, `illustrates`, `tracks`, `personalizes`, `references`, `gateway`, and `offers-content`.

## Integrity boundary

The graph is an organizational model. An edge does not establish that a theological, historical, scientific, academic, commercial, identity, or credential claim is true or verified. Research evidence, provenance, review state, payment verification, authentication, and protected access remain separate concerns.

Browser-local graph state is convenience state only and is not authentication, authorization, payment proof, or a verified credential.

## Acceptance criteria

1. `/knowledge/` loads independently with no external runtime dependency.
2. Nodes and relationships render from a versioned dataset.
3. Selecting a node reveals its connected relationships.
4. Relationship targets can be selected without leaving the graph.
5. Existing GEI routes remain the destinations for actual system experiences.
6. Mobile layout remains usable.
7. Local state does not claim authoritative identity, payment, or credentials.
8. V1.0.7 claims remain limited to implemented functionality.
