# V1.0.11 — GEI Module Action Adapter Layer

## Purpose

V1.0.11 introduces explicit module-owned action contracts between the GEI Command Orchestration layer and the systems that own the destination experience.

Architecture:

`USER COMMAND → COMMAND ENGINE → MODULE ACTION CONTRACT → OWNING MODULE ROUTE → MODULE EXPERIENCE → TIMELINE`

## Delivered

- `actions/action-data.js` defines versioned module action contracts.
- `actions/action-engine.js` validates and dispatches those contracts.
- Command Engine v1.0.11 delegates recognized commands through the adapter layer.
- Laboratory commands can carry experiment-specific routing hints.
- Command Center loads the action layer directly for deterministic startup.
- Platform Integration loads the action layer globally.
- Timeline records module-action dispatch events.

## Contract shape

Each module contract identifies:

- owning module
- contract version
- command/action ID
- human label
- action kind
- safe navigation route

The adapter layer may dispatch an action and provide a routing hint. It does not become the owner of module state.

## Ownership boundary

Module Action Adapters do **not**:

- authenticate users
- authorize protected resources
- verify payments or entitlements
- issue credentials
- mutate research evidence, claims, provenance, or review authority
- create authoritative academic or identity records
- perform engineering design calculations

The module that owns a resource remains responsible for its state and security.

## Acceptance criteria

1. Action contracts load without external runtime dependencies.
2. Recognized commands resolve through the adapter layer.
3. Unknown commands continue to fail safely.
4. Module routes remain registry-owned.
5. Command events continue to populate the local timeline.
6. Module-action events are observable in the local timeline.
7. Laboratory commands can carry an experiment route hint.
8. No client-side payment, authentication, or credential authority is introduced.
9. Existing V1.0.10 command behavior remains compatible.
10. Mobile and reduced-motion behavior remains intact.

## Future extension

Later releases may add richer module-owned action APIs, parameter validation, deep-link state handoff, protected server actions, authenticated identity, and server-side audit records. Those capabilities require their own security and ownership boundaries and are not implied by V1.0.11.
