# GEI Platform V1.0.4 — Unified Learning Progress & Achievement Layer

## Purpose

V1.0.4 turns the V1.0.2 session and V1.0.3 profile foundation into a unified local progress presentation layer. It derives activity from existing GEI systems instead of inventing credentials or authoritative records.

## Implemented

- `progress/progress-data.js` — canonical achievement and learning-system definitions.
- `progress/progress-engine.js` — unified progress snapshot and achievement derivation engine.
- `progress/progress.css` — responsive progress experience styling.
- `progress/index.html` — mobile-first Unified Progress Center.
- Platform Registry now exposes the Progress module at `/progress/`.
- Unified navigation now recognizes the Progress route.
- Existing Laboratory XP, runs, and completed experiments are surfaced.
- Existing Research review/note activity is surfaced.
- Existing Platform module visits and Profile personalization are surfaced.
- Academy uses an explicit optional adapter: progress is shown only when a real Academy progress state exists.
- Achievement unlocks persist locally with timestamps.
- Unified XP is presented as existing Laboratory XP plus locally derived achievement XP.
- Reset controls are provided for local achievement state.

## Activity Sources

| System | Existing local source | V1.0.4 use |
|---|---|---|
| Platform / Session | `gei-session-v1.0.2` | Visitor, page views, module visits |
| Laboratory | `gei-lab-v0.7` | Runs, completed experiments, existing Lab XP |
| Research | `gei-research-state-v05` | Review and research-note activity |
| Profile | Shared session profile | Persona and display-name personalization |
| Academy | Optional adapter keys | No fabricated Academy progress |

## Achievement Model

V1.0.4 provides seven local milestones:

1. First Step
2. Systems Explorer
3. Lab Runner
4. Lab Builder
5. Researcher
6. Personalized
7. Research Explorer

Achievement XP is derived from unlocked milestones and is separate from the Laboratory's existing XP source.

## Integrity Boundary

V1.0.4 does **not** provide:

- authentication
- authorization
- verified identity
- payment verification
- researcher credentials
- academic certification
- server-side entitlement authority

All browser-local progress is convenience state. Clearing browser storage can remove it. Local achievement state must not be represented as an official credential or proof of participation.

## Acceptance Criteria

- Unified Progress Center loads as an independent static page.
- Existing V1.0.2 visitor identity is reused when session state is available.
- Existing Laboratory activity is represented without replacing the Lab engine.
- Existing Research activity is represented without changing research semantics.
- Profile personalization is represented without treating it as verified identity.
- Academy progress is never fabricated when no Academy state exists.
- Progress and achievement state remain responsive on mobile.
- Progress route is discoverable through the shared Platform Registry/navigation.
- No payment credentials or authentication secrets are introduced.

## Next Logical Build

**V1.0.5 — GEI Credential & Research Portfolio Presentation Layer** should be considered only after V1.0.4 browser verification. Any future credential system must distinguish local achievements from server-verified credentials.
