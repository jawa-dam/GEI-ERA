# V1.0 — GEI Platform Core

## Purpose
V1.0 establishes the shared platform layer that connects the existing GEI systems into one coherent application architecture.

## Core systems
- Control Room — central navigation
- Explore — structured content discovery
- Academy — learning experiences
- Research — evidence, sources, claims, interpretations, provenance
- Laboratory — interactive conceptual experiments
- Media — image, video, audio, and book metadata
- Marketplace — products and access tiers
- Vault — premium resource access

## Platform Core
`platform/platform-core.js` provides a small provider-neutral state layer for active module, recent history, visits, and platform version. State is stored locally for convenience only. It is not authentication, authorization, or payment verification.

`platform/platform.css` provides shared platform navigation/card primitives.

`platform/index.html` is the V1.0 platform hub and system directory.

## Integrity boundaries
The platform does not treat browser storage as proof of payment or identity. Existing Commerce rules remain in force: real purchases require trusted server-side/provider verification.

Research records remain structured as source material, evidence, claims, interpretations, review state, and provenance. A platform record does not by itself establish that a GEI interpretation is historically or scientifically proven.

Laboratory experiences remain conceptual educational models rather than engineering design calculations.

## Release acceptance criteria
1. Platform hub loads independently.
2. Shared platform state initializes without external runtime dependencies.
3. Core systems are discoverable from one platform surface.
4. Mobile layouts remain usable.
5. Existing V0.3–V0.9 module architecture remains intact.
6. No payment credentials are placed in client code.
7. No browser-local state is represented as authoritative payment or identity proof.
8. V1.0 claims are limited to implemented functionality.

## Next phase
V1.0 can subsequently be extended with authenticated identity, server-backed profiles, unified search/indexing, protected media delivery, production payment verification, analytics, and additional Hostinger deployment hardening without changing the conceptual boundaries established here.
