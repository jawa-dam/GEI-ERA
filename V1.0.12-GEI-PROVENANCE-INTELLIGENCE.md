# V1.0.12 — GEI Provenance Intelligence & Audit Trail Layer

## Purpose
V1.0.12 adds a structured traceability layer for GEI platform activity. It standardizes provenance events so commands, module actions, navigation, session activity, discovery, knowledge, profile, progress, portfolio, and research-facing references can be described consistently.

## Architecture

`event → actor → action → module → target → source → occurredAt → recordedAt → context → evidenceRefs → integrity`

The layer provides:
- Versioned provenance vocabulary and JSON Schema.
- Browser-local provenance event storage with bounded retention.
- Validation of required provenance fields, event types, and registered modules.
- Inspection of individual provenance records.
- Global capture of platform, command, module-action, session, discovery, knowledge, profile, progress, and portfolio events.
- A dedicated `/provenance/` inspection surface.
- Platform Registry and Integration support for the Provenance module.
- Compatibility with V1.0.11 module-action dispatch events.

## Traceability model

A provenance record describes the relationship between an observed platform event and its source/context. `evidenceRefs` identify references when supplied; they do not establish that a claim or interpretation is true.

## Integrity boundary

The V1.0.12 client layer is **not** an authoritative audit ledger. Browser-local storage is not sufficient for authenticated identity, tamper-evident audit evidence, payment verification, credential issuance, legal records, or authoritative research provenance. A production audit system should use trusted server-side storage, authenticated actors, access controls, retention policy, integrity protection/signing, and independent verification.

## Acceptance criteria

1. `/provenance/` loads independently and remains mobile usable.
2. Provenance records validate against required fields and registered event types/modules.
3. Command execution produces a provenance event.
4. Module-action dispatch produces a provenance event.
5. Platform navigation can be traced.
6. Events can be inspected and cleared locally.
7. Platform Integration loads provenance globally.
8. Research evidence/claims/provenance are not mutated by this layer.
9. No payment, authentication, authorization, credential, or protected-state authority is introduced.
10. Claims about audit status remain explicitly local/unverified.
