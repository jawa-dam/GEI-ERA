# V1.0.10 — GEI Command Orchestration & Cross-System Action Layer

## Purpose

V1.0.10 extends GEI Unified Search from discovery/navigation into a bounded command and action-dispatch layer.

The command system accepts supported natural-language-like commands, resolves them against a curated registry, records a browser-local command event, and routes the request to the owning GEI module.

## Architecture

```text
USER COMMAND
     ↓
GEI COMMAND ENGINE
     ↓
COMMAND REGISTRY
     ↓
OWNING MODULE ROUTE
     ↓
MODULE EXPERIENCE
     ↓
TIMELINE ACTIVITY EVENT
```

## Implemented

- `commands/command-data.js` — curated supported-command registry.
- `commands/command-engine.js` — normalization, resolution, execution, recent-command state, and command events.
- `commands/command.css` — responsive Command Center presentation.
- `commands/index.html` — `/commands/` Command Center.
- Platform Registry registration for the Command Center.
- Platform Integration loads command data and engine globally.
- Unified Search can dispatch a recognized command before falling back to search results.
- Activity Timeline records `gei-command:execute` events.
- Ctrl+Shift+K / Cmd+Shift+K focuses the Command Center input.

## Ownership boundary

The Command Engine is an orchestration layer, not an authority layer.

It does **not**:

- authenticate users;
- authorize protected resources;
- verify payments or entitlements;
- mutate commerce state;
- alter research evidence, claims, interpretations, or provenance;
- issue academic credentials;
- establish authorship or identity;
- perform engineering calculations;
- represent browser-local activity as an authoritative record.

Each module remains responsible for its own data, permissions, and authoritative state.

## Acceptance criteria

1. `/commands/` loads independently.
2. Supported commands resolve deterministically.
3. Commands route through the Platform Registry rather than hard-coded privileged actions.
4. Search can hand recognized commands to the orchestrator.
5. Command execution creates a browser-local Timeline event.
6. Unknown commands fail safely without navigation.
7. Recent command history remains local and clearable.
8. Mobile layout remains usable.
9. No payment, identity, credential, research-authority, or protected-access claims are introduced.
10. Existing V1.0.9 search behavior remains available as the fallback path.

## Future extension

Later versions may add module-owned action adapters, command parameters, richer intent parsing, server-backed workflows, and authenticated actions. Those capabilities should be added only when the owning module explicitly exposes the corresponding authority and security boundary.
